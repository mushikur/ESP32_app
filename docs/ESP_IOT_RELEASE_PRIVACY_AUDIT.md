# ESP IoT release privacy and branding audit

Audit date — 11 November 2026. Evidence comes from the Android source manifest, the existing merged release manifest and APK, locked dependency configuration, Dart and Kotlin source, and the earlier Phase 9 report. Confirm the final merged manifest and dependency graph again when producing the distribution artifacts. [Phase 9 report](ESP_IOT_PHASE_9_TEST_REPORT.md)

## Data and permissions

| Data or operation | Evidence and release impact |
| --- | --- |
| Local device inventory and history | App-private SQLite holds endpoint addresses, board IDs, registration metadata, activity kinds and times, and usage times. History is capped at 300 rows globally and cascades on device removal. The database is ordinary SQLite and is separate from credential storage. [Database](../app/lib/features/devices/device_database.dart) |
| Profiles, passwords and pairing tokens | API profiles and their optional credentials use Flutter Secure Storage. Secure pairing tokens use the same plugin and are scoped to the verified origin, board ID, and optional certificate pin. The plugin defaults use AES-GCM with Android Keystore-protected key wrapping. No production secret was found in the inspected app source or learning assets. [API profile storage](../app/lib/features/connection/profile_store.dart) · [Secure pairing](../app/lib/features/connection/secure_pairing.dart) |
| Removal and revocation | Removing a device deletes its active registry record and activity. A local cleanup record remains until the app clears the dashboard and secure storage and retries after interruption. Remote revocation is a separate **Remove pairing** operation on a reachable board. Publish both actions so users understand the scope. [Registry cleanup](../app/lib/features/devices/device_registry.dart) · [Connection screen](../app/lib/features/connection/device_connection_screen.dart) |
| Preferences and sensor samples | Flutter’s preferences API stores onboarding, dashboard layouts and Learn & Build progress in Android DataStore. Learning progress includes language, checkpoint completion and activity days. Sensor histories are bounded to 60 samples per control in the active session. [Learning progress](../app/lib/features/learn/learn_progress.dart) · [Dashboard layout](../app/lib/features/dashboard/dashboard_layout.dart) · [Device session](../app/lib/features/connection/device_session.dart) |
| Camera and QR | The merged manifest includes `CAMERA` through `mobile_scanner`. Camera and autofocus are optional Android features. The scanner opens from Discover and has a denial and manual-entry path. The validated QR payload includes endpoint and identity information plus an optional TLS fingerprint. Authentication tokens and pairing codes are separate. [QR UI](../app/lib/features/discovery/pairing_qr.dart) · [QR schema](../app/lib/features/discovery/local_endpoint.dart) |
| Google scanner dependency | The installed `mobile_scanner` 7.5.0 Android build uses bundled ML Kit Barcode Scanning 17.3.0 by default. The inspected merged manifest includes the ML Kit initialization provider and Google DataTransport services. Google documents on-device processing for scan inputs and outputs and separate diagnostic and usage metrics. ESP IoT has no first-party account, analytics, ad, crash-upload, or remote-control backend in the inspected code. Review Play Data safety using the SDK disclosure and the exact final dependency set. [ML Kit Android data disclosure](https://developers.google.com/ml-kit/android-data-disclosure) |
| User-initiated exports | Sketch export writes the bounded `.ino` file to a document URI chosen in Android’s system picker. The user can choose local or provider storage. The app needs no broad file permission for this. **Copy** sends the selected sketch or URL to the Android clipboard. [Sketch export bridge](../app/android/app/src/main/kotlin/com/example/esp_iot/SketchExportBridge.kt) · [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) |
| Backup and transfer | The baseline disables cloud Auto Backup with `android:allowBackup="false"`. Some manufacturers can still transfer app data device to device. The release rules explicitly exclude SharedPreferences, databases and the DataStore directory, covering encrypted credentials, device history, legacy migration records and other preferences held in the same files. The rules apply to Android-managed backup and transfer. They leave app updates and the user’s document exports alone. Actual device-to-device transfer behavior still needs device testing. [Android backup behavior](https://developer.android.com/identity/data/autobackup) · [Android 11 and earlier rules](../app/android/app/src/main/res/xml/backup_rules.xml) · [Android 12 and newer rules](../app/android/app/src/main/res/xml/data_extraction_rules.xml) |
| Debug output | App code uses user-facing error messages and preview redaction for common credential-like keys and the configured legacy credential. The generated plugin registrant logs plugin registration exceptions. SDK logs, screenshots and diagnostic exports remain separate from the app’s privacy promises. Remove private addresses, QR codes, credentials and unrelated phone notifications from public QA artifacts. [Status preview](../app/lib/features/connection/device_session.dart) · [Phase 9 report](ESP_IOT_PHASE_9_TEST_REPORT.md) |

### Permission explanation

| Permission | User-facing explanation |
| --- | --- |
| Camera | ESP IoT uses the camera to scan a pairing QR when you choose **Scan pairing QR**. If access is denied or the camera is unavailable, use **Manual address** in Discover. Scan images are processed on the device. |
| Internet and network state | Android grants these capabilities at install time. ESP IoT uses them to check your Wi-Fi connection and communicate with compatible devices on your local network. On supported SDK 36 builds, Android does not present a separate local network permission dialog by default. |
| Wi-Fi multicast | Android grants this at install time. ESP IoT uses multicast discovery to listen for compatible devices on your Wi-Fi network. |
| Sketch export | Android’s picker lets you choose where one sketch is saved. The app does not request general access to your files or photos for this action. |

The audited app does not request location, notifications, Bluetooth, USB OTG, or broad storage access. Android 16 local network protection is opt-in for testing. A future target SDK 37 or higher must handle Android’s local network runtime permission or a compatible system-mediated flow. [Android local network permission](https://developer.android.com/privacy-and-security/local-network-permission)

## Distribution and branding

- The baseline release manifest labels the app **ESP IoT** and points to the branded `espiot_launcher`. Android 7.x uses the vector fallback. Android 8 and newer use the adaptive foreground and background. Android 12 and newer use the existing animated splash. The Flutter workspace and launch art reuse the same brand mark. [Launcher resources](../app/android/app/src/main/res) · [Flutter artwork](../app/lib/core/ui/esp_artwork.dart)
- The baseline adaptive resource has foreground and background layers. It has no dedicated monochrome layer for launchers that use themed icons. Themed icon behavior and launcher presentation require device verification. The unused template `ic_launcher.png` resources are not referenced by the baseline app manifest.
- The baseline APK uses `com.example.esp_iot`, version name `0.1.0` and version code `1`. The previous installed debug app uses the same identity with a debug signature. A release signed with a different certificate cannot replace it in place. An owner-controlled release identity and key are important before sharing a build intended for future updates. [Android signing and updates](https://developer.android.com/studio/publish/app-signing)
- Learn & Build includes seven bundled lessons and sketches. The app declares Flutter Material icons and uses system font rendering, including the monospace family for code. No custom font or in-app store listing assets were found in the inspected app asset list. [App asset list](../app/pubspec.yaml)
- Before a Play submission, replace the draft publisher and contact placeholders and publish the policy at a public URL. Set the URL and complete Data safety in Play Console using the final app and SDK behavior. The Settings privacy entry gives users the on-device explanation. No Play compliance or publication is asserted by this audit. [Privacy policy draft](PRIVACY_POLICY_DRAFT.md) · [Play Console app review instructions](https://support.google.com/googleplay/android-developer/answer/9859455)

## App disclaimer

ESP IoT is for learning and control of compatible devices you own or have permission to operate. Check your board’s pinout, voltage, and wiring before applying power. Commands can change physical outputs. Keep people clear of moving parts and verify the device’s actual state if a command is delayed, rejected, or unconfirmed. Use a physical cutoff and appropriate supervision for hazardous hardware. The app’s Stop action depends on the device and connection, so it must never be your only emergency stop.
